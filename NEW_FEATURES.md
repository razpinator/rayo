Rayo Roadmap: Evolution into a High-Performance Data Processing LanguageRayo pairs the readability and ergonomic elegance of Python-like syntax with the speed, memory safety, concurrency, and single-binary portability of Go.  While Python dominates data science, real-world data engineering pipelines often suffer from runtime overhead, the Global Interpreter Lock (GIL), high memory footprints, and multi-language operational debt (e.g., Python wrappers calling C/C++ or Rust cores). By transpiling to Go, Rayo has a unique architectural opportunity to serve as an expressive, high-throughput data processing language.  Below is the strategic feature roadmap designed to make Rayo a powerhouse for data processing.  1. Ergonomic Syntax & Language Primitives for DataData manipulation requires fluid transformations without deeply nested function calls or repetitive reassignments.  1.1 Native Pipeline Operator (|>)Enable stream transformations that read left-to-right, transpiling directly to efficient, inline Go function calls without allocation overhead.  Python# Rayo Syntax
data = (
    read_parquet("events.parquet")
    |> filter(row => row.status == 200)
    |> group_by("region")
    |> summarize(
        avg_latency = mean(latency),
        p99_latency = quantile(latency, 0.99)
    )
    |> write_parquet("summary.parquet")
)
1.2 First-Class Anonymous Records / Ad-hoc ProjectionsData pipelines frequently shape, drop, and rename fields. Forcing explicit Go struct definitions for intermediate pipeline stages creates massive boilerplate.  Feature: Rayo should automatically infer anonymous Go structs for ad-hoc projections, tuple unpacks, and column selects.  Go Target: Transpiles to anonymous struct { FieldA string; FieldB int } instances.  1.3 Vectorized Operations & Broadcasting SyntaxSupport element-wise array operations natively rather than requiring explicit loops:  Python# Vectorized element-wise math
adjusted_scores = raw_scores .* 1.25 .+ baseline_offset
Go Target: Transpiles down to tight, bounds-check-eliminated, cache-friendly Go loops (or SIMD assembly stubs where appropriate).  1.4 Structural Pattern Matching & Null-CoalescingSemi-structured data (JSON/NDJSON, event logs) contains irregular payloads and missing attributes.  Pattern matching on schemas and payloads:  Pythonmatch event:

        flag_vip(event)

        process_refund(rest)

        log_standard(event)

In-Memory Tabular Representation & Engine StrategyA data language lives and dies by its DataFrame and memory architecture. Wrapping naive maps ([]map[string]any) is too slow and cache-unfriendly for gigabyte-scale datasets.  2.1 Native Apache Arrow IntegrationInstead of building a custom columnar engine from scratch, Rayo should bind directly to the official Apache Arrow Go implementation ([github.com/apache/arrow/go](https://github.com/apache/arrow/go)).  Zero-Copy Interop: Read and write Arrow record batches directly to/from Parquet, DuckDB, Polars, and PyArrow.  Columnar Memory: Contiguous, cache-aligned memory with validity bitmasks for missing values.  Inter-Process Exchange: Seamless handoff to GPU or Python analytical nodes via Arrow Flight or Shared Memory (Plasma/IPC).  2.2 First-Class DataFrame Abstraction with Lazy EvaluationProvide a high-level DataFrame and LazyFrame type in Rayo's standard library:  Eager Mode: For rapid prototyping, exploration, and small files.  Lazy Plan Optimization: Compute execution graphs, push down filters/projections to storage layers (e.g., Parquet column pruning), and execute in batches.  2.3 Unified Missing Value Semantics (NA / null)Go uses default zero-values (0, "", false), which causes ambiguity in data processing (e.g., zero revenue vs. unrecorded revenue).  Rayo should implement unified nullable series backed by Arrow validity bitmaps or Option[T] representations that map cleanly to Go pointers or masked slices without performance cliffs.  3. High-Throughput Concurrency & StreamingHarness Go’s runtime scheduler and goroutines to completely outclass Python's GIL and heavyweight multiprocessing.  3.1 Parallel Iterators & Pipeline Concurrency (pmap)Provide built-in keywords or standard library functions for concurrent stream mapping:  Python# Concurrent batch processing across 16 worker goroutines
results = (
    read_stream("s3://bucket/huge-dump.ndjson", chunk_size=10_000)
    |> pmap(process_batch, workers=16)
    |> write_parquet("output/")
)
3.2 Out-of-Core Stream GeneratorsSupport generator functions (yield) that transpile directly into Go buffered channels (chan T) or bounded chunk iterators.  Enables datasets significantly larger than system RAM to flow through ingestion, filtering, and aggregation stages with predictable, bounded memory limits.  4.
